# Canonical Financial Proof-Obligation Architecture

## Purpose

The proof-obligation architecture converts normative financial invariants into explicit mathematical, evidentiary, implementation, and verification debt.

Every canonical invariant SHALL have at least one canonical proof obligation.

---

## Traceability Chain

Invariant
-> Proof Obligation
-> Required Premises
-> Formal Target
-> Counterexample Condition
-> Evidence Requirement
-> Implementation Requirement
-> Verification Requirement
-> Discharge State

---

## Status Separation

ASSERTED != FORMALIZED

FORMALIZED != TESTED

TESTED != PROVED

PROVED != DISCHARGED

NO_COUNTEREXAMPLE_OBSERVED != PROVED

IMPLEMENTED != PROVED

PUBLISHED != PROVED

---

## Initial Condition

All proof obligations generated by FIN-ARCH-06 begin:

OPEN

No proof obligation may begin as:

PROVED
DISCHARGED
COMPLETE
VERIFIED

---

## Discharge Architecture

A proof obligation may advance only through explicit state changes.

Recommended lifecycle:

OPEN
-> FORMALIZED
-> TESTED
-> PROVED
-> DISCHARGED

Alternative outcomes:

OPEN
-> BLOCKED

OPEN / FORMALIZED / TESTED
-> FAILED

Any state
-> NOT_APPLICABLE

only where non-applicability is explicitly justified.

---

## Counterexample Principle

A single valid counterexample to a universal invariant is sufficient to prevent proof discharge under the current formulation.

Counterexamples SHALL be preserved.

They SHALL NOT be deleted merely because the architecture is later repaired.

---

## Premise Discipline

Every proof must identify its premises.

A proof established under restricted premises SHALL NOT be generalized beyond those premises without a separate proof.

---

## Implementation Discipline

Passing implementation tests can support a proof obligation.

Implementation behavior alone does not establish a universal mathematical proof unless the obligation is explicitly defined over that finite implementation state space and the state space has been exhaustively covered.

---

## F1-F8 Role

The Financial Eight are not merely publications.

Each paper SHALL:

- consume existing OPEN proof obligations,
- formalize a defined subset,
- introduce new obligations only where genuinely required,
- supply counterexamples,
- supply implementation mechanisms,
- supply verification evidence,
- identify which obligations remain OPEN.

No paper may silently mark inherited proof debt complete.
